Digital Twin Sensor

Enterprise context does not live in documents. It lives in how work actually happens — what people attend to, in what order, what they abandon and return to. This is a working sensor that captures that signal on one machine, governs it before it is stored, and exports only what a policy gate admits. Then scales the same contract across a fleet.

02 · The capture problemHow context is captured

Thirty years of knowledge management failed because it asked people to describe their work. Descriptions are what people believe they do. This captures the trace instead — and treats every stage after the first as a deliberate reduction.

Depth 1 · default

Attention shape

Foreground application, redacted window title, timestamp and dwell time, derived work domain, and the app-switching sequence. Enough to reconstruct what someone was working on and when they lost the thread.

Depth 2 · opt-in

Browser context

Tab title and domain for the active browser. URL path, query and fragment stay off by default and are configured independently — the domain tells you the workstream, the query string tells you far more than anyone consented to.

Depth 3 · allowlist only

Interface labels

Redacted UI labels and roles from macOS Accessibility, for named applications only. No screenshots, no keystrokes, no video. Depth 3 exists for apps that expose nothing useful in their window title.

Each depth is a separate decision with a separate switch. Nothing escalates on its own:

# attention shape only — the default
digital-twin-sensor collect-once

# add browser tab context, leave URL internals off
digital-twin-sensor configure --depth 2 --browser-tab-details on \
  --browser-url-path off --browser-url-query off

# add redacted interface labels, for one named app
digital-twin-sensor configure --depth 3 --accessibility-surface-details on \
  --accessibility-app "Ibo Pro Player"

03 · The boundaryWhat it refuses to collect

A worker who believes they are being logged changes what they do — and you capture the performance instead of the practice. So the boundary is not a setting. It is the product.

Collected by default
  • active application
  • redacted window title
  • timestamp and dwell time
  • derived work domain
  • app-switching sequence
  • graph, sphere and pack metadata
Never collected
  • keystrokes
  • clipboard contents
  • microphone or camera
  • raw screenshots or video
  • browser cookies
  • passwords or tokens
  • raw URL paths, queries, fragments
  • any raw cloud upload

The dashboard carries a captured / not-captured ledger, a pause and resume control, and a retention purge — visible to the person being observed, not buried in an admin console. Consent that cannot be inspected is not consent.

04 · SystemThe whole architecture, on one machine

Every box below runs locally. The only thing that crosses a boundary is a context pack that a gate has already approved.

05 · Under the hoodHow the system defines attention

Attention is not time on screen. Dwell alone rewards the window you left open while you went to lunch. It is modelled as a distribution with a shape — five vectors, recomputed on every profile pass.

Where & when

Domain and rhythm

Dwell distributed across work domains, plus an hour-of-day histogram. Together they answer where attention goes and when it goes there.

Movement

Transitions

Domain-to-domain transition counts. How attention moves carries more about interrupted work than how long it rested anywhere.

Drift

Entropy and divergence

Shannon entropy for concentration, and KL divergence of the last five days against the last fourteen. Past 0.2, this week does not look like the fortnight.

That divergence is treated as a trigger rather than a statistic: when it fires, retrieval automatically adds a differential filter. Filters are picked from cues in the question itself, and evidence is weighted by the filter before content matching is applied at all.

proportionalThe default. What actually held attention, weighted by dwell and returns.
inverse“missing”, “ignored”, “should have” — surfaces what was neglected. Absence treated as evidence, which no document store can do.
differential“changed”, “spike”, “anomaly” — what shifted against baseline.
recurrent“again”, “keeps coming back” — what was returned to, and how many times.
sequential“then”, “order”, “workflow” — the order things were actually done in.
collective“team”, “everyone” — cohort signal, and the only filter that passes through the aggregation floor below.

Final rank is attention × content. Content alone finds the document. Attention decides whether the person was actually working on it.

06What joins the layers

Six layers, each consuming the one below and discarding more than it keeps. The weights below are the ones in the code, not an illustration.

The synthesis layer Built

Many sensors, one answer

One sensor answers what was this person doing. An institution needs what is the work here — without any individual trace being reconstructable from the output. So the floor comes first: a theme is emitted only when a set number of distinct subjects independently support it.

It reads gated working spheres, never raw events, keyed by opaque hashes. Below-floor themes are withheld and counted, so an operator sees that suppression happened rather than quietly receiving a thinner answer. Confidence weights corroboration across people above volume from any one person, so a single prolific subject cannot manufacture a theme alone.

The harness Built

Measuring whether the context is any good

Unit tests prove a function returns what it was told to return. They cannot tell you whether the context handed to an agent is relevant enough to be useful and tight enough to be safe. A golden set runs end to end and scores recall, noise, leakage, evidence age, pack size and gate decisions. A leakage canary reaching an export fails the build outright, whatever the recall score.

It earned its place on the first run — catching events sixty days old being exported inside a three-day window, because the window was advisory in the builders and enforced only at the database. Twenty-two unit tests had not found it.

07 · ScaleFrom one machine to an enterprise fleet

One sensor is a personal tool. The interesting question is what happens at ten thousand endpoints — where the knowledge you are trying to reach is spread across the operators who never write anything down. The scale-out model keeps the same contract: raw events stay on the endpoint, and only gated summaries move.

Syncs by default
  • device and watchdog health
  • collector and policy version
  • privacy-gate counts
  • redacted working-sphere summaries
  • redacted context-graph summaries
  • context packs approved for export
  • pause / resume state
  • retention expiry counts
Never syncs
  • the raw event ledger
  • raw URLs
  • screenshots
  • keystrokes
  • clipboard
  • microphone or camera data
  • credentials, tokens or secrets
Endpoint requirements Built
  • stable device identity and name
  • background collector, dashboard and watchdog services
  • visible collection status and local policy
  • redaction before persistence
  • doctor and health reporting
  • local pause, resume, purge and export controls
Packaging targets Designed
  • macOS — signed .pkg, LaunchAgent, MDM profile for Accessibility
  • Windows — signed .msi, Windows Service, Edge/Chrome connector
  • Linux — .deb / .rpm, systemd user service
  • Docker — control plane and demo environment

08 · The ladderWhat changes as the sensor spreads

A sensor on one laptop is a productivity toy. The interesting thing about this class of system is that its value does not scale linearly with deployment — it changes kind at each tier. New context appears that was not visible one level down, and with it a new set of things that can run without anyone asking.

01

Individual

Sees: your own attention trace — what you opened, abandoned, returned to.

Runs itself: resume packs after every interruption. An agent that starts a session already knowing what you were doing at 4pm yesterday and which of three threads went cold.

Costs: nothing but your own consent.

02

Team

Sees: the seam between people — where work is handed over and what falls in the gap.

Runs itself: expertise routing by observed practice rather than job title. Duplicate-effort detection. Onboarding that shows a new joiner what the senior person actually does, not what the process document claims.

Costs: the first real consent conversation. Ten people can identify each other from anonymised data.

03

Department

Sees: the process as practised, next to the process as written. They are never the same document.

Runs itself: a live process map that maintains itself. Exception patterns surfaced before they become incidents. The forty-person knowledge risk register, kept current without an interview programme.

Costs: aggregation floors become mandatory. Below a threshold, every metric is a performance review nobody agreed to.

04

Business unit

Sees: the shadow operating model — the routes work actually takes between functions.

Runs itself: hand-off latency measured rather than estimated. Controls that are routinely worked around, flagged with the reason people work around them. Change impact observed in weeks instead of surveyed in quarters.

Costs: the findings will embarrass someone. A system that only reports comfortable results will be ignored, and should be.

05

Organisation

Sees: institutional memory as a maintained asset rather than a departure risk.

Runs itself: agents grounded in how this firm actually decides, not how a generic model assumes firms decide. Succession exposure computed continuously. Judgment captured at the moment it is exercised, so it compounds instead of evaporating.

Costs: works councils, regulators and a genuine internal argument about what the firm is entitled to observe.

06

Sector

Sees: practice compared across firms — federated, with no raw data ever leaving any of them.

Runs itself: benchmarks of how work is done rather than what it produced. Shared exception taxonomies. The distance between what a regulation says and what supervised firms actually do, visible to both sides.

Costs: this only works with federated summaries and a floor on cohort size. Anything less is a competitive intelligence leak with a governance label on it.

07

Country

Sees: where skills actually sit, as observed practice rather than as job titles on a census.

Runs itself: the effect of a policy change on how people work, measured in weeks. Skills mapping that does not rely on what people claim on a CV. Early warning on which capabilities are concentrating in too few heads.

Costs: this stops being a company's decision. It is a question for a society, and it should be asked out loud before it is answered by default.

08

World

Sees: a map of how human work is actually done, kept current.

Runs itself: in principle, the training substrate for systems that understand work rather than describe it — the thing every frontier lab is currently trying to approximate from text.

Costs: at this tier the engineering is the easy half. The consent architecture is the whole problem, and it is not solved by anyone yet.

09Use the repository

Clone it, run it against your own machine for a week, and look at what the admission gate refuses to let out. That is the fastest way to understand what a governed context layer actually costs.

git clone https://github.com/gagans23/digital-twin-sensor.git
cd digital-twin-sensor
python3 -m venv .venv && source .venv/bin/activate
pip install -e .

digital-twin-sensor init
digital-twin-sensor collect-once
digital-twin-sensor profile
digital-twin-sensor ui            # dashboard at 127.0.0.1:8765

# derive context and export a gated pack
digital-twin-sensor graph --days 14
digital-twin-sensor activities --days 14
digital-twin-sensor context-pack --days 14 --target kiro --format markdown

# measure whether that context is any good, and synthesise across subjects
digital-twin-sensor harness --fail-under 0.8
digital-twin-sensor synthesize --min-subjects 5

# operate it safely
digital-twin-sensor doctor
digital-twin-sensor pause
digital-twin-sensor purge --older-than-days 30 --yes
