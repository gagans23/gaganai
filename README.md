## What this is

The Philosophical Ledger is two things on one site, unified by a single idea — **the ledger**:

- **Essays** — the *human ledger*: a practitioner's field notes on moving AI from impressive
  demos to governed execution inside a regulated bank (operating models, control planes,
  institutional memory). Long-form, mechanism-first, with the working shown.
- **The AI Situation Room** — the *machine ledger*: a live intelligence product that tracks
  verified AI market moves, classifies them as signal vs noise through a structural "gate,"
  and resolves them into a few directions a leader must govern — with act-now / watch-next /
  what-would-change-our-mind framing.

The unifying thesis: a ledger records judgments and their outcomes — what a regulator audits
and a model learns from. Governance is what lets the loop run. That idea runs through the
essays and through the Situation Room's signal gate.

The site is intentionally narrow: it is built for one reader — **a senior leader governing AI
in a regulated institution** — not for a general AI-news audience.

## How it's built

- **No framework, no build step.** Plain HTML/CSS/JS served statically. Pages are hand-authored;
  the Situation Room data files are generated by a Python pipeline (stdlib only) and committed.
- **GitHub Pages** hosts it free; the custom domain `gagansachdeva.com` is proxied through
  Cloudflare (Web Analytics beacon on every page).
- **Type system:** Fraunces (display) · Spectral (body) · IBM Plex Mono (labels) — three faces,
  site-wide, no page exceptions. Variable-font optical sizing + OpenType features
  (oldstyle figures in prose, discretionary ligatures in display, lining tabular figures for
  stats).
- **A daily cloud pipeline** (GitHub Actions) generates the day's intelligence, rebuilds the
  graph + gate, and bakes the radar edition — fully self-driving, no local cron.

## Information architecture

**Three primary doors** (the nav on every page): **Writing · Signal · About**.

- **Writing** — the essays, plus the Library (podcast claims ledger + working bookshelf) and the
  monthly briefs, folded in as cards on the writing index.
- **Signal** — the Situation Room. The door lands on `signal.html` (the gate — the lead view).
  A secondary "altitude" bar offers **Signal · The Feed** (2 views). The Graph and Briefs are
  secondary pages reachable via contextual links, not co-equal doors — the gate is the product,
  the raw feed is provenance.
- **About** — a dedicated `/about.html` with the story, the work, four beliefs, credentials, and
  the ledger-spine framing.

The homepage is a **funnel**, not an index: hero (thesis) → live signal (proof it's alive) →
Writing/Start here → about teaser → subscribe. It routes; it doesn't reproduce the site.

## The intelligence engine

A stdlib-only pipeline (Python, no dependencies beyond the cloud generator) that runs daily in
GitHub Actions and turns raw news into governed decisions:

```
data/signal-ledger.jsonl   (append-only, deduped by url+title — the persistent record)
        │
        ├─ automation/build_knowledge_graph.py  → data/knowledge-graph.json   (powers /graph.html)
        ├─ automation/build_signal_gate.py      → data/signal-gate.json       (powers /signal.html)
        └─ automation/render_radar.py           → radar.html + feed.xml + radar/<date>.html
```

- **`build_knowledge_graph.py`** — accumulates the ledger into a co-occurrence graph of entities
  across the five layers (Energy → Silicon → AI Factories → Models → Agents). Powers the
  connection graph.
- **`build_signal_gate.py`** — runs every ledger entry through five structural tests
  (Mandate / Money / Machinery / Corroboration / Criterion-shift); a stimulus is **noise** until
  it trips one. Surviving signals are attached to hand-authored **attractors** (the editorial
  inference layer, in `data/attractors.json`). Output: `data/signal-gate.json`.
- **`render_radar.py`** — bakes the daily radar edition (lead story + supporting cards + the
  five-layer cake + market chatter) into `radar.html`, the RSS `feed.xml`, and a per-date
  archive under `radar/`. **Never hand-edit `radar.html`** — edit `automation/radar.template.html`
  and rebake.
- **`update_daily_intelligence.sh`** — the local orchestrator (the cloud job mirrors it).

The accounting invariant: `mapped + unresolved + noise == stimuli`. A structural signal that
hasn't accumulated enough evidence to bind into a direction stays visible in `other` — never
silently counted as explained.

## The noise gate (the moat)

The gate is the experience moat no AI aggregator has. Every competitor dumps news; this site
shows the **classification** — and the **rejection**:

- Each direction card shows the **structural tests it passed** as chips (Mandate / Money /
  Machinery / Corroboration / Criterion-shift) — "why this is signal, not noise," made tangible.
- The **"what changed since last gate" delta** — `build_signal_gate.py` keeps a per-date history
  (`data/signal-history.jsonl`) and computes a diff vs the previous gate: new signals, strength
  changes. No aggregator shows a thesis evolving over time.
- The **rejected-items drawer** — the exclusions are inspectable ("filtering only earns trust if
  you can see what was filtered out").
- Every signal links to its source and shows which test it tripped — provenance you can see.

The attractor *prose* (the decisions, actions, disconfirming evidence) is hand-authored in
`data/attractors.json`. The gate is automated; the interpretation is editorial.

## Design system

- **Faces:** Fraunces (display, variable opsz) · Spectral (body) · IBM Plex Mono (labels).
- **Palette:** warm paper `#f2efe6` / amber signal `#b3661f` / deep `#9b6b2d` on the inner
  "ledger" pages; night `#0a0d0e` + light ink for the cinematic **dark lead bands** on the
  homepage hero, the signal page, and the about page. Rhythm: **dark lead → light body**.
- **Shared shell:** `assets/editorial-shell.css` — the vertical "THE PHILOSOPHICAL LEDGER"
  marginalia, the brand mark, sticky altitude bar, mobile nav, and print rules. Inner pages load
  it after their critical inline CSS.
- **OpenType:** `font-feature-settings` — `kern/liga/calt/onum` for body (oldstyle figures),
  `kern/liga/calt/dlig` for display (discretionary ligatures), `lnum/tnum` for stat numbers.
- **Motion:** deliberate, weighty easing (`cubic-bezier(0.16,1,0.3,1)`); a staggered hero
  entrance; a scroll-driven provenance machine (Ledger→Graph→Gate→Brief); a scroll-scrubbed
  convergence spine that draws itself then runs **"voting" pulses** along the paths; and a
  continuous flowing-dash animation on the graph edges. All motion respects
  `prefers-reduced-motion`.

## Experience features

- **Signal page** — executive decision brief: lean dark lead with a "See the 4 directions" CTA,
  a slim gate-stats bar, the four direction cards (strength pills + structural-test chips +
  "Open the decision brief"), the convergence spine, the full decision briefs (act-now /
  watch-next / disconfirming), the method, and the rejected items.
- **Role-filtered views** — view the signal page as **CRO / CTO / COO**; selecting a seat dims
  the non-relevant directions so a leader sees what matters for their role.
- **Board-meeting PDF** — a "Board brief · Print / PDF" button + a print stylesheet that yields
  a clean, decision-ready brief (headline + stats + the four directions), all chrome hidden.
- **Reading experience** — essays have a reading-progress bar, an auto table of contents, a
  Fraunces drop cap, and end-of-essay **next-in-the-reading-path** CTAs that carry the Start
  here sequence through the archive.
- **Radar feed** — "The raw feed" (provenance), compact bordered story cards with amber accents,
  grouped New today / Ongoing context, the five-layer cake, and market chatter.

## Local development

```bash
# Preview (the site is static — any static server works)
python3 -m http.server 8080
# → open http://localhost:8080

# Regenerate the intelligence locally (no API key needed — reads the existing ledger)
python3 automation/build_knowledge_graph.py
python3 automation/build_signal_gate.py
python3 automation/render_radar.py
```

The gate, graph, and radar bake are **deterministic** — running twice on the same ledger
produces the same output. The cloud generator (`automation/gcc-ai-newsletter/run_daily.py`)
needs the `PARALLEL_API_KEY` secret.

## Deployment & the daily pipeline

- **GitHub Pages** deploys `main` automatically (no action required on push).
- **`daily-intelligence.yml`** runs at 06:00 GST daily: it generates the day's signals (Parallel
  API), updates the knowledge graph, runs the noise gate (now also persisting history + the
  delta), **and bakes the radar edition in-workflow** — generation and baking publish atomically
  in one run (GitHub won't trigger a separate workflow from a `GITHUB_TOKEN` push, so baking
  in-workflow is what keeps the edition fresh). Gated on the `PARALLEL_API_KEY` secret.
- **`bake-radar.yml`** is the safety net: rebakes `radar.html` on template/data changes and on a
  06:30 schedule.
- **`monthly-brief.yml`** auto-publishes the prior month's brief on the 1st.
- **Cloudflare** fronts the custom domain and provides Web Analytics.

## Configuration

- `assets/site-config.js` — `buttondownUsername` (the newsletter) and
  `cloudflareAnalyticsToken`. Edit these once; every page reads them via `site.js`.
- **Secrets:** `PARALLEL_API_KEY` (and optional `PARALLEL_BASE_URL`) in
  Settings → Secrets and variables → Actions. Without the key, the daily generation no-ops
  cleanly.
- See `SETUP.md` for the domain DNS records, Buttondown, and Cloudflare setup.

## Conventions

- **Commit prefix** shows authorship: `[codex]`, `[claude]`, or `[cloud]` (the bot).
- **Cache-busting:** CSS/JS carry `?v=` query strings — bump the version when you change a
  shared asset so browsers refetch. HTML pages are cached by the browser for ~10 minutes
  (GitHub Pages `max-age=600`), so a hard reload may be needed to see HTML changes immediately.
- **Layer classifier** (`LAYER_RE` / `classify_layer`) is duplicated in `render_radar.py`,
  `build_knowledge_graph.py`, and `assets/radar.js` — **change all three together.**
- **`render_radar.py` and `assets/radar.js` must agree** — the server bake and the client
  hydration must produce the same lead/order. The `score_story`/`ageInDays` logic is duplicated;
  keep them in lockstep.
- **Never hand-edit `radar.html`, `feed.xml`, or `radar/<date>.html`** — edit the template /
  data and let `render_radar.py` (or CI) bake. Archived `radar/*` editions are frozen snapshots.
- **No fourth font.** The type system is Fraunces / Spectral / IBM Plex Mono — everywhere.
