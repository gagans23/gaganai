Context Is The Moat

Enterprise AI will not be won by the largest context window. It will be won by the institution that can safely admit the most useful context into the moment of work.

Gagan Sachdeva ~9 min read Digital twins, agents, governance, memory

The phrase digital twin still carries the scent of factories: a turbine, a building, a supply chain, a model that shadows the thing so operators can simulate decisions before taking them. The interesting question now is what happens when the thing being modeled is not a machine, but a working human inside an institution.

That can become a bad idea quickly. A shallow version becomes surveillance with better vocabulary. It watches everything, explains little, and mistakes exhaust for insight. The better version is narrower and more ambitious: a governed context layer that helps agents understand the work without stripping dignity, privacy, or judgment from the person doing it.

This is the idea behind the Digital Twin Sensor I have been building. The sensor is not trying to clone a person. It is trying to preserve the shape of work: what drew attention, what artifact mattered, what decision was made, what evidence supported it, what uncertainty remained, and what should be forgotten.

The thesis: the value of an agentic system scales with the institutional context it can admit per unit of model attention. Not merely with the size of the model, and not merely with the size of the window.

Why context is scarce

Most enterprise AI conversations still over-index on the model. That made sense when capability was the bottleneck. It is less true now. The models keep improving. The hard part is getting the right context into the system at the right time, with proof that it came from the right place and permission to use it.

A bank does not only need a good answer. It needs to know which policy was current, which customer segment was in scope, whether a human approved the step, what data was masked, what exception was taken, and whether the result can be explained six months later. That is not a prompt-length problem. It is a context admission problem.

The twin should be a graph, not a profile

A profile collapses a person into traits. A graph preserves relationships. The useful unit is not "Gagan likes X" or "Gagan works on Y." The useful unit is: this task used this document, followed this meeting, changed this code, referenced this policy, and produced this decision under this constraint.

Signals app focus, browser context, file touch, meetings, tickets Semantics topics, workflows, entities, uncertainty, decision moments Privacy PII masking, secret detection, retention, consent, purpose limits Memory durable patterns, evidence, provenance, confidence, expiry Admission what an agent can retrieve, cite, act on, or must ignore

This is where a digital twin becomes useful for agents. The agent does not need a personality sketch. It needs a situated memory of the work. The graph tells it what context is adjacent to the current task and which parts are admissible.

The privacy gate is the product

Continuous collection only becomes defensible when privacy is not bolted on later. Names, cards, tokens, secrets, private URLs, personal messages, and sensitive text must be handled before storage, sync, and retrieval. The twin should show what it refused to remember as clearly as what it captured.

This is a product design choice as much as an architecture choice. Users should be able to see the collection depth, pause a sensor, inspect recent captures, understand why something was masked, and delete or expire memory. Enterprises will not trust a black box that watches work. They may trust an instrument that proves its restraint.

What this adds to the paper

The paper that inspired this build, arXiv:2605.15505, is valuable because it treats the human twin as something that keeps learning from new traces. My extension is to make the twin operationally enterprise-grade: local-first capture, typed context graphs, privacy gates, provenance, administrative policy, and a UI that lets a person understand the model being built around their work.

The moat is institutional, not individual

The compounding advantage is not that one person gets a clever assistant. It is that an institution learns how its best work actually happens. The organization starts to preserve judgment instead of only preserving outputs. It can see repeated friction, common exceptions, tacit playbooks, and decision paths that used to disappear at the end of the day.

That is the moat. Not context as raw capture. Context as governed memory. Context that can be admitted into the right task, refused in the wrong one, cited when challenged, and improved when outcomes arrive.
